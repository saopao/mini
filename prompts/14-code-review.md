# 14. 多角色代码 Review

请为当前实现做多角色 Review。

请先阅读：

- `AGENTS.md`
- `docs/03-design-system.md`
- `docs/05-data-model-and-formulas.md`
- `docs/06-page-acceptance.md`
- `docs/10-test-cases.md`

请从 4 个角色独立审查：

## 角色 1：视觉一致性审查

检查：

- 是否违反 design tokens。
- 是否新增随机颜色。
- 是否重复写按钮/卡片样式。
- 间距、圆角、字号是否统一。

## 角色 2：产品体验审查

检查：

- 页面是否回答用户最关心的问题。
- 是否有空状态。
- 是否有异常状态。
- 是否有下一步动作。
- 文案是否是经营语言。

## 角色 3：业务逻辑审查

检查：

- 公式是否统一调用 calculator。
- 边界值是否处理。
- 修改模型后是否同步刷新。
- 删除记录后是否同步回滚。
- 是否出现 NaN / Infinity 风险。

## 角色 4：微信小程序兼容审查

检查：

- uni-app 写法是否适合微信小程序。
- rpx、safe area、tabBar 是否正确。
- 输入框和键盘是否可能遮挡。
- 页面生命周期是否合理。

输出格式：

```md
# Code Review

## 视觉一致性
### 通过项
- xxx
### 风险项
- xxx
### 必须修改
- xxx

## 产品体验
...

## 业务逻辑
...

## 微信小程序兼容
...

## 总结
- 必须修复：
- 可后置：
- 不建议修改：
```

不要直接改代码，先输出 Review。
