# 截图对比与视觉验收

## 目的

视觉质量不能只靠一次生成。每个页面都必须经过截图、对比、修复和复验。二版迭代不按旧设计图做像素或结构还原，验收重点是实际实现效果、`docs/03-design-system.md`、Wot Design Uni 组件基线和跨端一致性；`reference/design-reference-v1.png` 只保留为旧版视觉语气参考。

跨端视觉一致性以 `docs/12-cross-platform-ui-consistency.md` 为补充标准。H5 和微信小程序端的卡片、按钮、输入框、页面背景和安全区必须分别验收。

## 基础流程

```text
页面初版
-> 本地运行
-> 截图
-> 对照设计图和设计系统评分
-> H5/微信小程序端一致性检查
-> 输出问题清单
-> 只修视觉问题
-> 再截图
-> 再评分
```

视觉 review 第一步只分析，不直接改代码。

## 评分维度

| 维度 | 分值 | 检查点 |
|---|---:|---|
| 视觉一致性 | 25 | 颜色、圆角、阴影、字号是否统一，H5 与小程序端是否一致 |
| 信息层级 | 20 | 最大数字、主按钮、核心结论是否突出 |
| 间距呼吸感 | 15 | 是否拥挤，卡片之间是否舒适 |
| 组件复用 | 15 | 是否复用基础组件和业务组件 |
| 小程序质感 | 15 | 是否像移动小程序，而不是网页或后台 |
| 文案质感 | 10 | 是否是经营语言，是否简短清楚 |

评分规则：

- 低于 85：必须继续修。
- 85-90：可进入下一页，但后续还要抛光。
- 90 以上：可进入内测候选。

## 视觉 Review 输出格式

```md
# 视觉 Review：页面名

## 总分
xx / 100

## 通过项
- xxx

## 最大的 5 个问题
1. 问题：xxx
   影响：xxx
   修改建议：xxx

## 不建议修改
- xxx

## 下一轮修复清单
- [ ] xxx
- [ ] xxx
```

限制：

- 不建议新增随机颜色。
- 不建议引入 Wot Design Uni 之外的通用 UI 库。
- 不建议改业务范围。
- 不使用“更高级”“更精美”这类空泛描述。
- 每个建议必须能落到字号、间距、组件、层级或文案。

## 视觉修复规则

视觉修复任务只允许：

- 调整间距。
- 调整字号。
- 调整圆角。
- 调整组件状态。
- 调整卡片层级。
- 调整文案长短。
- 调整颜色到已有 token。

不允许：

- 改业务逻辑。
- 改数据结构。
- 改公式。
- 新增范围外功能。
- 引入 Wot Design Uni 之外的新通用 UI 库。
- 绕过 Wot Design Uni 和项目基础组件另写页面级通用控件。
- 为单个页面临时创建一套按钮或卡片样式。

## 常见问题

### 页面显得廉价

常见原因：

- 卡片圆角不统一。
- 阴影过重。
- 间距太小。
- 字体层级混乱。
- 按钮太矮。
- 主色使用不克制。

修复方向：

- 回到设计 token。
- 主按钮高度保持移动端可点击。
- 卡片内边距统一。
- 每页只突出一个最大数字或结论。

### 页面显得拥挤

常见原因：

- 一屏卡片太多。
- 文案太长。
- 指标全部平铺。
- 缺少分组。

修复方向：

- 合并次要信息。
- 使用折叠公式说明。
- 首屏只放核心状态。
- 次要信息下移。

### 页面不像小程序

常见原因：

- 顶部栏不适配。
- 底部按钮不考虑安全区。
- 交互像桌面网页。
- 输入框太复杂。

修复方向：

- 保持移动端安全区。
- 底部留足操作空间。
- 减少 hover 和鼠标逻辑。
- 表单输入保持轻量。

### 经营感不足

常见原因：

- 只有数字，没有解释。
- 文案像财务系统。
- 不告诉用户下一步。

修复方向：

- 每个核心数字配一句经营解释。
- 保存后给“还差多少/已超过多少”。
- 风险卡给具体行动建议。

## 每页截图验收表

```md
# 页面截图验收：页面名

## 基础
- [ ] 页面可正常进入
- [ ] 无控制台错误
- [ ] 无白屏或闪烁
- [ ] 数据为空时有引导
- [ ] 数据异常时有提示

## 视觉
- [ ] 页面背景符合 token
- [ ] 卡片圆角统一
- [ ] 按钮样式统一
- [ ] 字号层级清晰
- [ ] 最大数字足够突出
- [ ] 没有随机颜色
- [ ] 没有挤压感
- [ ] H5 与小程序卡片样式一致
- [ ] H5 与小程序按钮样式一致
- [ ] H5 与小程序输入框样式一致
- [ ] H5 与小程序底部安全区一致

## 交互
- [ ] 主按钮位置清晰
- [ ] 点击反馈明显
- [ ] 返回路径清晰
- [ ] 表单错误提示明确
- [ ] 键盘不遮挡核心输入

## 业务
- [ ] 公式正确
- [ ] 风险标签正确
- [ ] 修改模型后能重算
- [ ] 删除记录后能重算

## 文案
- [ ] 使用经营语言
- [ ] 不堆会计术语
- [ ] 不承诺收益
- [ ] 每张卡片都有明确结论
```
