# Codex 工作流

## 目标

把后续 AI 协作从“让 Codex 自由实现”改成“按阶段、按文档、按验收闸门交付”。

本项目当前还没有代码工程。除非用户明确要求开始实现，否则 Codex 只允许处理文档、方案、评审和工程流程。

## 核心原则

1. 每次只做一个明确任务。
2. 每个任务先读对应文档，再行动。
3. 每个阶段都有进入条件、产出物和退出标准。
4. 公式、设计、页面范围、交互规则不能由 Codex 临时发挥。
5. 页面实现后必须经过截图对比、代码 review 和链路回归。
6. 低于验收标准不进入下一阶段。

## 阶段总览

```text
0 文档对齐
1 技术路线确认
2 项目骨架
3 设计系统与基础组件
4 计算引擎
5 Store 与 Repository
6 逐页实现
7 页面截图视觉 Review
8 多角色代码 Review
9 全链路回归
10 内测准备
```

## 阶段 0：文档对齐

目标：让 Codex 读懂项目边界，不做任何实现。

输入：

- `AGENTS.md`
- `docs/00-project-brief.md`
- `docs/01-product-positioning.md`
- `docs/03-design-system.md`
- `docs/04-information-architecture.md`
- `docs/05-data-model-and-formulas.md`
- `docs/06-page-acceptance.md`
- `docs/07-interaction-rules.md`

产出：

- 产品定位复述。
- V1 必做页面。
- V1 暂不做功能。
- 设计系统硬约束。
- 公式和数据边界。
- 需要用户确认的问题。

退出标准：

- 无文档冲突。
- 若有冲突，先列出冲突，不继续后续阶段。

## 阶段 1：技术路线确认

目标：在写代码前确认工程底座。

默认候选：

- uni-app
- Vue 3
- TypeScript
- Pinia
- SCSS
- 微信小程序优先，保留跨端能力

规则：

- 如果用户确认该技术栈，后续实现按 `docs/05-data-model-and-formulas.md` 执行。
- 如果用户选择 Taro、原生微信小程序或其他方案，先更新 `docs/05-data-model-and-formulas.md` 和 `AGENTS.md`，再实现。
- 技术栈未确认前，不初始化代码工程。

退出标准：

- 技术栈明确。
- 目录结构明确。
- 本地存储、状态管理、图表和测试方案明确。

## 阶段 2：项目骨架

目标：只建立可运行空工程和页面路由。

只允许做：

- 项目目录结构。
- 页面路由。
- TabBar。
- 8 个空页面。
- 基础入口。

不允许做：

- 业务逻辑。
- 复杂样式。
- 公式。
- Store。
- 登录、支付、云同步。

退出标准：

- 工程可运行。
- 首启进入欢迎页。
- TabBar 仅包含看板、记账、实验室、我的。
- 所有页面可进入。

## 阶段 3：设计系统与基础组件

目标：先稳定视觉语言，再实现业务页面。

只允许做：

- 设计 token。
- 全局样式。
- 基础组件。
- 业务组件骨架。

建议组件：

- 页面容器。
- 顶部栏。
- 卡片。
- 按钮。
- 输入框。
- 金额输入。
- 分段控件。
- 标签。
- 空状态。
- 指标卡。
- 风险标签。
- 报告结论卡。
- 趋势图骨架。
- 方案对比卡。

不允许做：

- 具体页面业务。
- Store。
- 公式。
- 随机颜色。
- 大型 UI 库。

退出标准：

- 后续页面都能复用这些组件。
- 颜色、圆角、间距、字号均来自设计系统。

## 阶段 4：计算引擎

目标：先保证经营测算正确，再接页面。

只允许做：

- 业务类型。
- 核心公式。
- 风险规则。
- 报告构建。
- 实验室模拟。
- 数字和日期工具。
- 行业模板。
- 公式测试。

不允许做：

- UI 页面。
- 本地存储。
- 真实埋点。

退出标准：

- `docs/10-test-cases.md` 的公式基准用例通过。
- 边界值不返回 NaN 或 Infinity。
- 风险规则有可解释文案。
- 公式函数保持纯函数。

## 阶段 5：Store 与 Repository

目标：建立本地优先、未来可替换的数据层。

架构原则：

```text
页面 -> Store -> Service -> Repository -> 平台存储
```

只允许做：

- 店铺模型状态。
- 记账记录状态。
- 报告和看板聚合。
- 本地存储封装。
- 数据清空。
- 基础埋点接口。

不允许做：

- 页面细节。
- 直接在页面读写 storage。
- 云同步真实接入。

退出标准：

- 保存模型后重开不丢。
- 新增、编辑、删除记录后聚合值正确。
- 修改模型后报告、看板、实验室基线同步重算。
- 清空本地数据后回到无模型状态。

## 阶段 6：逐页实现

推荐顺序：

1. 欢迎页。
2. 行业选择页。
3. 开店测算页。
4. 经营报告页。
5. 今日看板页。
6. 快速记账页。
7. 实验室页。
8. 我的页。

每次只做一个页面。

每个页面实现前必须读取：

- `AGENTS.md`
- `docs/03-design-system.md`
- `docs/06-page-acceptance.md`
- `docs/07-interaction-rules.md`
- 当前页面对应的 `prompts/` 任务说明

每页退出标准：

- 页面能进入。
- 空状态、错误态、加载态存在。
- 关键交互可用。
- 没有 V1 范围外功能。
- 无明显视觉溢出。
- 通过该页面验收标准。

## 阶段 7：页面截图视觉 Review

目标：防止页面风格漂移。

流程：

```text
实现页面 -> 本地运行 -> 截图 -> 对照设计图评分 -> 只修视觉 -> 再截图
```

规则：

- 视觉 review 先只输出问题，不直接改代码。
- 低于 85 分必须修。
- 85-90 分可进入下一页，但后续需要抛光。
- 90 分以上可进入内测候选。

详细规则见 `docs/09-visual-review.md`。

## 阶段 8：多角色代码 Review

每个页面或模块完成后，至少从 4 个角度 review：

- 视觉一致性。
- 产品体验。
- 业务逻辑。
- 小程序兼容。

Review 先输出问题清单，不直接大范围修改。

必须优先处理：

- 公式错误。
- 数据不同步。
- NaN / Infinity。
- 关键链路阻断。
- 明显违反设计系统。
- 引入 V1 暂不做功能。

## 阶段 9：全链路回归

必须跑通：

```text
首次打开
-> 欢迎页
-> 开始测算
-> 行业选择页
-> 选择奶茶/饮品
-> 开店测算页
-> 输入参数
-> 生成报告
-> 经营报告页
-> 保存模型并进入看板
-> 看板页
-> 记一笔收入 200
-> 看板刷新
-> 记一笔支出 120
-> 看板刷新
-> 实验室页
-> 提高客单价
-> 查看前后对比
-> 我的页
-> 修改模型
-> 报告、看板、实验室同步刷新
-> 清空本地数据
-> 回到欢迎页或无模型引导
```

退出标准：

- 无 P0/P1 问题。
- 公式测试通过。
- 本地存储测试通过。
- 主要页面视觉评分达到内测标准。
- 没有 V1 范围外功能。

## 阶段 10：内测准备

进入条件：

- 全链路回归通过。
- `docs/11-launch-checklist.md` 的内测前检查通过。
- 至少 10 组真实或接近真实的参数样本跑通。

内测观察指标：

- 首次建模完成率。
- 报告页保存率。
- 首次记账转化率。
- 7 天内 3 次记录比例。
- 实验室使用率。
- 用户是否能复述“每天至少要卖多少”。

## 任务输出格式

每个 Codex 任务完成后必须输出：

```md
## 修改文件
- xxx

## 完成内容
- xxx

## 未做事项
- xxx

## 自查结果
- 是否符合 V1 范围：
- 是否符合设计系统：
- 是否覆盖空状态和异常状态：
- 是否影响公共组件或公式：

## 验证方式
- xxx

## 需要用户确认
- xxx
```

## 停止条件

出现以下情况必须暂停并询问用户：

- 需要新增 V1 范围外功能。
- 需要引入新 UI 库。
- 需要改技术栈。
- 需要接入云服务、登录、支付。
- 需要面向用户输出 AI 经营建议。
- 公式口径不明确。
- 设计系统无法覆盖当前需求。
- 文档之间出现冲突。

## 文档同步规则

- 改产品范围：更新 `docs/00-project-brief.md`。
- 改定位：更新 `docs/01-product-positioning.md`。
- 改视觉：更新 `docs/03-design-system.md` 和 `docs/09-visual-review.md`。
- 改页面：更新 `docs/06-page-acceptance.md`。
- 改交互或公式：更新 `docs/07-interaction-rules.md`、`docs/10-test-cases.md`、`docs/05-data-model-and-formulas.md`。
- 改 AI 流程：更新 `docs/08-codex-workflow.md`、`prompts/` 和 `AGENTS.md`。
