# 数据模型、公式与模块边界

## 当前状态

当前项目已经建立 uni-app 初版代码工程。本文定义代码实现必须遵守的数据对象、公式口径、模块边界和本地优先数据层。

当前初版技术路线：

- uni-app
- Vue 3
- TypeScript
- Pinia
- SCSS
- 微信小程序优先

若后续改用 Taro、原生微信小程序或其他方案，应先更新本文、`docs/08-codex-workflow.md` 和 `AGENTS.md`。

## 架构原则

V1 采用本地优先架构：

```text
页面 -> Store -> Service -> Repository -> 平台存储
```

硬性边界：

- 页面不直接读写平台 storage。
- 页面不直接写复杂经营公式。
- 公式函数必须是纯函数。
- Repository 必须可替换，便于未来接云同步。
- mock 数据必须集中管理，不能散落在页面。
- 埋点先定义接口，可先 console 或本地记录。

## 推荐目录边界

| 模块 | 责任 | 禁止 |
|---|---|---|
| `pages` | 页面路由、页面交互、展示编排 | 直接写公式、直接读写 storage |
| `components/base` | 通用 UI 组件 | 绑定业务模型 |
| `components/business` | 业务展示组件 | 管理全局状态 |
| `stores` | 页面所需状态、派生数据入口 | 直接写平台 API |
| `services/calculator` | 公式、风险规则、报告构建、实验室模拟 | 引用页面组件 |
| `services/repository` | 本地存储封装、未来同步接口 | 写业务公式 |
| `constants` | 行业模板、分类、静态枚举 | 写运行时状态 |
| `utils` | 日期、数字、格式化 | 引入业务流程 |
| `styles` | token、全局样式 | 页面临时颜色 |

## 数据对象

### 店铺模型

必须包含：

- 店铺 ID。
- 店铺名称，可选。
- 城市，可选。
- 行业 ID。
- 行业名称。
- 店铺状态：筹备中或已开业。
- 前期投入。
- 每月固定支出。
- 每月营业天数。
- 毛利率。
- 回本周期。
- 客单价。
- 最大日单量，可选。
- 创建时间。
- 更新时间。

可选拆分：

- 投入拆分：装修、设备、押金、加盟费、首批物料、转让费、其他。
- 固定支出拆分：房租、人工、水电、物业、软件、其他。

### 行业模型

必须包含：

- 行业 ID。
- 行业名称。
- 默认毛利率。
- 毛利率参考范围。
- 默认客单价。
- 客单价参考范围。
- 默认营业天数。
- 风险等级。
- 风险标签。
- 常见固定成本项。
- 常见支出分类。
- 建议话术。
- 风险阈值。

### 记账记录

必须包含：

- 记录 ID。
- 店铺 ID。
- 日期。
- 类型：收入或支出。
- 金额。
- 分类。
- 备注，可选。
- 创建时间。
- 更新时间。

### 经营报告

必须包含：

- 店铺 ID。
- 月目标利润。
- 月毛利目标。
- 月流水目标。
- 日流水目标。
- 日单量目标。
- 日固定成本摊销。
- 风险标签。
- 优先级建议。
- 一句话结论。
- 生成时间。

### 看板快照

必须包含：

- 日期。
- 日流水目标。
- 今日收入。
- 今日支出。
- 今日估算利润。

- 7 天趋势。

## 公式服务边界

公式统一由 calculator service 提供。

基础公式以本文和 `docs/07-interaction-rules.md` 为准：

```text
每月目标利润 = 前期投入 / 回本周期
月毛利目标 = 每月固定支出 + 每月目标利润
月流水目标 = 月毛利目标 / 毛利率
日流水目标 = 月流水目标 / 每月营业天数
日单量目标 = 日流水目标 / 客单价
日固定成本摊销 = 每月固定支出 / 每月营业天数
今日估算利润 = 今日收入 * 毛利率 - 日固定成本摊销 - 今日其他支出
回本进度 = 累计估算利润 / 前期投入
```

边界要求：

- 输入非法时返回明确错误或由表单层阻断。
- 不允许向页面返回 NaN、Infinity。
- 金额展示格式由 format 工具处理，不在公式函数内格式化。
- 单量展示可向上取整，公式值保留原始小数。

## Repository 边界

V1 至少需要：

- 当前店铺模型 repository。
- 记账记录 repository。
- 应用设置 repository。
- 事件日志 repository，可选。

建议存储 key：

| Key | 内容 |
|---|---|
| `kd_shop_model` | 当前店铺模型 |
| `kd_ledger_records` | 记账记录 |
| `kd_app_settings` | 设置、免责声明已读状态 |
| `kd_event_logs` | 本地事件日志，可选 |

Repository 必须支持：

- 读取。
- 写入。
- 删除。
- 清空。

记账记录额外支持：

- 列表。
- 新增。
- 编辑。
- 删除单条。

## Store 边界

### Shop Store

负责：

- 当前模型读取。
- 保存模型。
- 修改模型。
- 清空模型。
- 行业模板带入默认值。

### Ledger Store

负责：

- 记录列表。
- 新增记录。
- 编辑记录。
- 删除记录。
- 按日期聚合收入和支出。

### Report Store

负责：

- 基于模型生成报告。
- 基于模型和记录生成看板快照。
- 生成 7 天趋势。
- 生成回本进度。
- 提供实验室基线。

Report Store 不直接写入业务记录。

## 基础埋点

V1 先定义事件，不强依赖第三方 SDK。

事件名：

- `welcome_view`
- `industry_select`
- `calculate_submit`
- `report_view`
- `store_create`
- `dashboard_view`
- `ledger_first_entry`
- `ledger_entry_create`
- `scenario_run`
- `profile_view`

埋点规则：

- 不采集手机号、位置、通讯录等非必要信息。
- 不记录用户输入的敏感备注全文，除非后续有明确隐私授权。
- 本地日志可用于调试，正式上线前需确认合规和清理策略。
